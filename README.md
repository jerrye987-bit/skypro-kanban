# Канбан-доска задач

## Функционал приложения

### 1. Аутентификация и авторизация

- **Вход в аккаунт** — форма входа с полями «Эл. почта» и «Пароль». Валидация: проверка формата email, минимальная длина пароля — 6 символов. Обязательные поля подсвечиваются красной рамкой при ошибке.
- **Регистрация** — форма регистрации с дополнительным полем «Имя». Переключение между формами входа и регистрации через роутинг (`/login`, `/register`).
- **Обработка ошибок** — текстовые сообщения об ошибках выводятся внутри формы (пустые поля, неверный формат email, короткий пароль, ошибка сервера при авторизации).
- **Выход из аккаунта** — двухэтапный процесс: сначала открывается попап с информацией о пользователе и переключателем темы, затем — модальное окно подтверждения «Выйти из аккаунта?» с кнопками «Да, выйти» и «Нет, остаться». После подтверждения пользователь разлогинивается и перенаправляется на страницу входа.

### 2. Управление задачами

- **Создание задачи** — модальное окно с полями: название, тема (Web Design / Research / Copywriting), описание, дата. Новая задача создаётся со статусом «Без статуса».
- **Просмотр задачи** — модальное окно с полным описанием задачи, темой, статусом и датой. Открывается по клику на карточку.
- **Редактирование задачи** — изменение названия, темы, статуса, описания и даты через модальное окно. Обновление данных на сервере.
- **Удаление задачи** — удаление карточки с подтверждением через модальное окно.
- **Отображение задач** — задачи распределены по пяти колонкам в зависимости от статуса: «Без статуса», «Нужно сделать», «В работе», «Тестирование», «Готово».

### 3. Перетаскивание карточек

- **Перетаскивание карточек между колонками** — реализовано на нативном HTML5 Drag and Drop API без внешних библиотек.
- **Визуальная обратная связь** — при перетаскивании карточка становится полупрозрачной с наклоном; колонка-приёмник подсвечивается пунктирной рамкой и фоном.
- **Оптимистичное обновление** — статус задачи мгновенно меняется в интерфейсе, затем отправляется запрос на сервер. Если перетащить карточку в ту же колонку, запрос не выполняется.
- **Защита от ложных срабатываний** — обработчик `dragleave` проверяет `contains(relatedTarget)`, чтобы колонка не мигала при движении курсора между дочерними элементами.

### 4. Тёмная и светлая тема

- **Переключение темы** — чекбокс «Темная тема» в попапе пользователя.
- **Сохранение выбора** — выбранная тема сохраняется в `localStorage` и восстанавливается при перезагрузке страницы.
- **Применение темы** — тёмная тема реализована через атрибут `data-theme="dark"` на корневом элементе. Стили тёмной темы вынесены в отдельный файл `main_dark.css`, загружаемый динамически. Все правила имеют префикс `[data-theme='dark']`, чтобы не влиять на светлую тему.
- **Поддержка темы во всех компонентах** — тёмная тема применена к: канбан-доске, карточкам задач, модальным окнам (создание, просмотр, подтверждение выхода), форме входа/регистрации, попапу пользователя, хедеру. В компонентах со scoped-стилями и `!important` тёмная тема добавлена через глобальные блоки `<style>` без `scoped` с `!important` для перебора специфичности.

### 5. Загрузка и обработка состояний

- **Skeleton-загрузка** — пока задачи грузятся с сервера, в каждой колонке отображаются плейсхолдеры (`TaskSkeleton`).
- **Пустое состояние** — если задач нет и загрузка завершена, показывается сообщение «Задач нет» с иконкой.
- **Баннер ошибки** — если бэкенд недоступен, вверху страницы выводится красный баннер с текстом ошибки.
